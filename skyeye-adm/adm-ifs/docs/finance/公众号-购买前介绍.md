---

很多老板、财务、门店负责人，其实不是不懂账，而是**账跟不上业务**：

- 销售出库了，收入还要财务再录一遍  
- 商城退了款，总账和门店余额对不上  
- 报销、工资、资产折旧，月底才想起补凭证  
- Excel 能凑合，一要审计、一要多租户、一要商城，就乱了  

Skyeye云把这件事做成一句话：

**业务审批通过，会计事件自动生成；凭证、过账、报表，跟着业务走。**

不是「再买一套独立财务软件」，而是 CRM、ERP、仓库、商城、人事薪资、固定资产——**同一套业务系统里的财务中枢**。

---

## 一、它解决什么问题？

| 痛点 | 有了业财一体之后 |
|------|------------------|
| 业务一套数、财务一套数 | 审批通过即推会计事件，同源同口径 |
| 月底集中补凭证 | 日常业务随办随记，月底主要核对与结账 |
| 商城与进销存账各算各的 | 支付预收、收货确认收入、退款冲账、提现打款全链路可入账 |
| 关账了还能改单推账 | 会计期间关闭后，相关审批会被拦住 |
| 税率、暂估、退货靠手工拆 | 应收/开票/采购票支持价税分离；销售退货可冲收入与成本 |

对标思路接近用友、金蝶一类「业务驱动凭证」的产品路径，但落地在你们已经在用的Skyeye云业务模块上，**不用再拆两套系统对接**。

## 一附、业务怎么流进财务？（买前看懂结构）

```text
客户应收/回款/开票     ─┐
供应商应付/付款/采购票 ─┤
仓库入出库（采销产零） ─┼─► 会计事件 ─► 凭证 ─► 余额 / 账龄 / 报表
费用申请→报销、借款     ─┤
商城支付→收货→退款→提现─┤
薪资核算/发放           ─┤
固定资产购入折旧报废    ─┘

另有一条「收付款台账」：只记回款付款开票进度，不出总账凭证。
```

要点（和详细说明书一致）：

- **出入库先进仓库再记账**，账实同步。  
- **商城先预收、收货再确认收入**，退款按是否已确认收入分流。  
- **关账后相关审批可被拦住**，避免关账月继续改账。  
- 流程图彩色版见交付文档 / 详细说明附录（发公众号时做成一张长图即可）。

## 二、买之前，你能得到什么？

### 1. 财务中枢能力（IFS）

- 会计期间：开账 / 业务关账 / 财务关账  
- 会计凭证：草稿、审核、过账、红字冲销、冲销关系可查  
- 科目余额、试算平衡  
- 凭证模板：按「业务事项」配置借贷科目，支持一键初始化默认模板  
- 业务会计事件台：每笔业务推账可查、失败可重试（幂等，防重复记账）  
- 财务报表、往来账龄、损益结转等  

### 2. 业务自动记账（已贯通的主链路）

- **销售侧**：应收确认（可拆销项税）、客户回款、销售开票、销售出库成本、销售退货冲收入与成本  
- **采购侧**：采购入库暂估、应付确认、供应商付款、采购发票（进项税）、采购退货  
- **仓库侧**：其他入出库、领退料、完工入库、盘点、调拨、零售/门店/换货/借还等出入库同步  
- **费用借款**：费用申请挂账 → 报销付款冲挂账；借款 / 还款  
- **薪资**：实发计提与发放，社保公积金与个税代扣代缴（可配置推账）  
- **固定资产**：购入、退货、报废、月结批量折旧  
- **商城**：支付记预收 → 确认收货确认收入并结转成本 → 退款冲预收或冲收入 → 结算 / 佣金 / 提现  

### 3. 适合谁？

- 已上或计划上Skyeye云 **CRM / ERP / 商城 / 人事 / 资产** 的企业与门店  
- 希望「业务人员照常审批，财务少做重复录入」的团队  
- 需要多租户、门店资金与总账可对账的零售 / 连锁场景  

### 4. 暂不适合什么预期？

请提前对齐预期，避免买后落差：

- 存货成本当前以物料规格「采购价/成本价」为主，**完整移动加权成本引擎**可后续增强  
- 商城确认收入**暂不按规格自动拆销项税**（应收事项、采购/销售发票仍支持价税分离）  
- 费用报销默认衔接「先申请挂账、再付款冲账」；纯直接报销需约定流程或手工凭证  
- 部分分析类页面（资金分析、发票统计、费用分析等）以展示为主，**不强制同步生成凭证**  
- 「收付款台账」≠ 已出会计凭证，对账时以事件台 + 凭证为准  

这些不影响日常主链路使用，属于持续迭代项。

## 三、和「只买财务模块」有什么不一样？

| | 传统独立财务 | Skyeye云业财一体 |
|--|--------------|----------------|
| 数据从哪来 | 财务再录或导 Excel | 业务单据审批直接驱动 |
| 商城 / 门店 | 往往另接或对不上 | 支付、收货、退款、提现同一事件体系 |
| 模板与科目 | 各做一套 | 统一凭证模板 + 默认科目初始化 |
| 关账控制 | 多在财务侧 | 期间关闭可阻断推账与相关审批 |

一句话：**财务不是旁路，是业务结果的会计表达。**

## 四、买前建议你确认的 5 件事

1. **是否已有 / 将上线** CRM 应收回款、ERP 采销仓、商城订单中的哪些模块？业财价值随业务模块覆盖面增大而增大。  
2. **财务是否接受「业务驱动凭证」**：日常以核对、改模板、结账为主，而不是每笔手录。  
3. **科目与账套**：能否按工业企业示意科目（或贵司科目）做一次初始化与模板核对。  
4. **关账纪律**：是否接受关账后业务改单/推账被限制。  
5. **商城租户**：个人店与企业店入账租户规则是否与贵司组织一致（可按门店/租户隔离）。  

确认这 5 点没问题，上线路径通常是：执行财务相关库表 → 初始化科目与默认凭证模板 → 抽测回款/付款/出入库/商城一单 → 再全面推广。
